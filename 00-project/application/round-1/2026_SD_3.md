# Study-material-grounded Exercise Generation and Practice Application

## My interpretation of the brief
The project is a source-grounded learning application that organizes material as separate study projects and transforms approved sources into a reviewable exercise bank and a practical learning workflow. Its purpose is not simply to ask an LLM to generate questions. Every generated question, reference answer, and explanation must remain traceable to specific source material, be editable before approval, and respond correctly when the underlying material changes.

The initial application should focus on a narrow subject area and no more than two exercise types: multiple-choice and short-answer questions. Multiple-choice scoring must be deterministic. Short-answer assessment may use AI, but it must compare the response with explicit criteria, explain the result using the approved source, and identify uncertainty instead of presenting an unreliable judgment as fact.

The project also requires measurable research and design decisions. It must compare question generation from full documents with generation from retrieved excerpts, and random exercise assembly with a constrained method that considers topic coverage, repetition, requested length, and previous attempts. Question quality, source traceability, assessment quality, latency, correction effort, and reproducibility must be evaluated separately.

## Proposed approach
I would organize the application around separate study projects, such as individual subjects or courses. Each project would have its own source library, topics, approved question bank, question sets, practice history, and isolated AI interaction context. The first version would accept well-defined text-based sources such as Markdown and plain text. Each document would be divided into stable, versioned study units so that questions and answers can retain precise source references and affected questions can be flagged when a source changes. Support for text-based PDF and additional formats could be added through the same document-processing boundary after the core workflow is validated.

For generation, the user could select an entire project, chosen topics, or exact parts of the material and provide instructions for the type and purpose of the required questions. The model would use only the relevant study units to produce draft multiple-choice or short-answer questions in a validated structure. The user would retain full control over the source scope and could inspect the supporting excerpt, edit the question, options, reference answer, explanation, difficulty, or topic, and approve it before it enters the question bank. Near-duplicate questions would be detected, and regeneration after a source update would remain a reviewable draft rather than silently replacing manual corrections.

The practice workflow would assemble multiple reusable question sets from the approved bank, each with its own source scope, difficulty, size, ordering, and practice history. Sets could be categorized by topic or section, left uncategorized for general practice, or mixed across selected material. Users could work through sections sequentially, request a broader project-level set, repeat difficult material, or configure a self-evaluation session around their own goals. Multiple-choice answers would be scored by application logic. For short answers, the AI would assess the response against predefined criteria and cited source material, explain its judgment, and send uncertain cases for review.

The AI integration could extend across the learning cycle rather than ending after question generation. Within the boundaries of the approved project material, it could help customize sets, explain questions and answers, identify areas needing more practice, and propose a review sequence or learning path based on selected goals and previous attempts. The user would remain able to inspect and control the selected topics, progression, and evaluation mode. These features would support practice without presenting AI-generated question quality or suggested progression as proof of learning effectiveness.

A focused chat or discussion view could allow the user to reference one or several questions and ask about the question text, options, answers, explanations, or related source material without losing access to the exercise itself. Conversations could be associated with the whole project, a question set, or selected questions while the context layer retrieves only the relevant source units, approved information, and necessary recent interaction. This would avoid repeatedly loading an entire project into the model context and would provide a clear basis for experimenting with bounded retrieval and conversation-context strategies.

For evaluation, I would use a manually checked dataset separated from material used to select prompts or models. I would compare full-document and retrieval-grounded generation for answerability, source correctness, repetition, correction effort, latency, and cost. I would also compare random and constraint-based set assembly for topic coverage, repetition, feasibility, reproducibility, and assembly time, while separately evaluating the reliability of short-answer assessment.

## Initial plan
1. Choose one subject for the first version and use multiple-choice and short-answer questions.
2. Create the project structure for sources, topics, questions, question sets, conversations, and practice results.
3. Let the user add text-based material, select the relevant parts, and keep a clear reference from every question back to its source.
4. Let the AI create instructed draft questions from the selected material, then allow the user to review, edit, and approve every part.
5. Build practice and scoring: exact scoring for multiple choice and source-based AI feedback for short answers.
6. Add categorized, general, sequential, mixed, repeated, and self-evaluation question sets.
7. Add source-grounded chat for selected questions, options, answers, and explanations, together with an AI-guided learning path.
8. Test the required generation and question-selection methods on the same material, then improve the interface and documentation.

## Additional information
I would intentionally begin with one narrow subject area, textual material, and the two required exercise types so that source correctness, dependency handling, assessment, and exercise selection can be tested thoroughly. The project-based library, attachment model, question sets, contextual interaction, and guided practice would be designed as parts of one integrated learning project, while broader document formats and additional educational features would be introduced only after the mandatory core is reliable.
