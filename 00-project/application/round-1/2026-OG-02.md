# Implementation of a Consistent Dynamic Game World in a Text Adventure Based on Large Language Models

## My interpretation of the brief
The project is a text-based interactive world in which an LLM generates responsive narrative while the application maintains the authoritative state of the world separately. The model should not be expected to remember or control every fact through conversation history alone. Characters, locations, objects, relationships, rules, and important events need persistent structured representations, and each accepted action must update both the narrative and the relevant state.

The central research and engineering challenge is long-term consistency. As the world grows, the system must prevent narrative and state drift: gradual contradictions, forgotten relationships, duplicated events, or consequences that no longer follow from earlier decisions. A saved session must resume coherently, and the system must define a clear boundary between deterministic program responsibilities and decisions delegated to the LLM. At least two context- or memory-management approaches should therefore be compared empirically rather than selecting one without evidence.

## Why I am a good fit for this project
I am strongly interested in AI harnesses: systems that go beyond a chat interface by coordinating context, memory, retrieval, rules, model output, validation, and persistent state. I have experimented with harnesses for different personal workflows, including adaptations of existing architectures and attempts to design custom components. This has made me familiar with the practical problem behind this brief: an LLM can produce convincing text, but a dependable application needs explicit mechanisms to preserve state, retrieve the right context, and prevent gradual inconsistency.

I find this project especially motivating because it combines applied AI with software architecture, state management, testing, and interactive design. The result can be creative and engaging for the user while still requiring precise engineering decisions that can be measured objectively.

## Proposed approach
I would begin with a small but complete text-adventure scenario and a clear separation between four components: the user interface, the deterministic world-state engine, the context and memory layer, and the LLM narrative layer. The user would submit an intended action; the LLM could propose narrative consequences and structured events, but the program would validate them before applying them to the authoritative world state. Invalid or contradictory outcomes would be rejected, corrected, or regenerated according to explicit rules.

Rather than attempting to design a universal story format only in the abstract, I would first select one representative story and model it from beginning to end. Its characters, locations, objects, relationships, rules, events, and possible scenarios would provide the first structured standard. Running realistic interactions against that story would reveal missing cases and weaknesses, allowing the representation and validation rules to be improved before they are generalized.

The interface could combine a readable story view, an interaction area, and concise information about the current world. In Player mode, the user would act through one selected character and the system would determine valid consequences. A controlled Game Master mode could permit authoritative events, management of multiple roles, or deliberate changes to the direction of the world. The active role and its permissions would be explicit, allowing role switching without confusing player intent with world-authoring authority. Where appropriate, the system could present several coherent candidate directions and let the user choose which branch becomes canonical.

Once the initial standard is stable, the system could initialize another project either from a user-selected theme or from an imported story. The AI would transform generated or imported material into the application's structured representation, identify uncertain or missing information for review, and validate it before the story becomes playable. Story-specific rules or configuration profiles could guide this transformation while preserving a common engine. The initial implementation would validate this approach on a limited set of representative scenarios instead of claiming universal support for every narrative form.

The persistent representation would track the minimum information necessary for consistency, including characters, locations, objects, relationships, significant events, and branches. A relationship and event graph could help the system retrieve only the parts of the world relevant to the current action. Save and resume would restore both the authoritative state and the narrative context required to continue coherently.

For the mandatory comparison, I would evaluate two high-level memory strategies: a structured world state combined with a controlled narrative summary, and a relationship- or event-oriented representation with relevance-based retrieval. Both would be tested on the same longer scenarios for contradiction and drift rate, context size, token use, retrieval quality, continuation quality, and growth over time. The exact schemas, prompts, and retrieval rules would be determined during specification and experimentation rather than fixed prematurely.

## Initial plan
1. Choose one manageable story and map its characters, locations, objects, relationships, rules, and events.
2. Use that story to create the first version of the structured story and world standard.
3. Run different scenarios, find missing cases or weak rules, and improve the standard.
4. Define what a player, a Game Master, the program, and the AI are allowed to change.
5. Build the interaction flow: the user takes an action, the AI suggests the result, and the program checks and applies valid changes.
6. Add the text interface, story branches, and save and resume.
7. Implement and compare two ways of giving the AI relevant story and world information during longer sessions.
8. Use the improved standard to test AI-created and imported stories, then check their consistency and missing information.

## Additional information
I would intentionally keep the first evaluated worlds small enough to test thoroughly. The architecture would be designed to accommodate richer story-import, Game Master, role-switching, and branching workflows, while the assessed implementation would prioritize state consistency, persistence, memory comparison, and reproducible evaluation.
